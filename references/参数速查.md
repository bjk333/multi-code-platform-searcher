## Cfg 策略常数（U-15 / T2-13，`$script:Cfg`；v1.37.8 起）

> 口径：只收"可调策略常数"；单位换算（`*1000` ms）、编码页（28591）、HTTP 状态码、`Format-Table` 列宽、`param` 默认值不算魔数。改数值只改 `Cfg`，调用点零字面量。

> **单位约定（U-82）**：时长键名**必须**以 `Sec` / `Ms` 结尾（与「单位」列一致）；Node 门（test-r4）按本表「单位」列校验——单位为 秒/毫秒 的键缺后缀 ⇒ 红。多键一行时「单位」按 ` / ` 与键一一对应。

### 实测墙钟量级（v1.53.10，2026-10-23 本机）

> 条件是**有代理且代理间歇性抖动**（当天代理多次 502 / 探活无结论）。数值只作量级参考，别当 SLA。
> 结构上先看公式：**最坏 = 预算 × 池数**（默认 120s/池；`-Auto` 最多 3 池 ⇒ 360s），池间缝隙另计。

- `-Platform All`（repo 单池，4 平台）：**13.2s**（当日早先同命令 30.9s，差在坏代理是否被快速收束）

- `-Auto`（repo + research，2 池）：**23.4 – 27.6s**；拆开看 repo ≈12s、research ≈6s，其余是规划 + 池间缝隙

> 引擎是**词法匹配**，不做语义理解。查询措辞直接决定召回，下面每条都有本机实测支撑。
> ★**本节的实测对照刻意不用表格** —— 本文件的表格会被 U-60 当作「参数表行」计数（踩过两次）。

- `-Auto "调研 rust 生态的异步运行时选型"` ⇒ 检索式 `rust async runtime`（v1.53.15 时被削成 `rust` ⇒ hello-algo / veloren 等无关高星项目）★
- `-Auto "向量数据库"` ⇒ 检索式 `vector database`（中文原句 ⇒ document.ai / funNLP / x86-bare-metal-examples，与主题无关）★
- `-Keyword "vector database" -Platform GitHub` ⇒ milvus ★46466 / tidb / quivr —— 单源对照，说明改写后的词本身是对的
- `-Auto "分布式锁的几种实现方式"` ⇒ `distributed lock` ⇒ ShedLock / redsync / redisson（中文原句 ⇒ Some-Many-Books / x86-bare-metal-examples）★

**中文主题词查询的路由（v1.53.22 起）**：命中内置主题词表（如 `向量数据库` / `分布式锁` / `中文分词` / `微服务` / `检索增强`）且**没有**「文档 / 论文 / 标准 / 最佳实践 / 最新 / 调研」这类研究信号、**不是提问/教程形状**（`什么是` / `如何` / `教程` / `原理`…）、也没有否定词 ⇒ 跑 **repo + research**（不加 code 池）。
此前这类查询一律判 `research_only`，**repo 池压根不跑** —— 改写生效了却没用上。纯问题（`什么是向量数据库` / `如何设计限流`）、无关查询（`今天天气怎么样`）、带研究信号的查询（`RAG 论文`）行为不变。
★跨源混排时包注册表（npm / crates.io / Packagist）可能排在仓库前面：只想看项目就加 `-Platform GitHub`，或用 `counts.repo` 判断本轮拿到几条仓库。

**选型/对比类查询（v1.53.15 起）**：含「选型 / 对比 / 比较 / 替代 / 哪个好 / 选一个 / 选哪个 / vs / comparison / compare / alternative / tradeoff」等词 ⇒ 跑 **repo + research**。此前这类查询误判 `research_only`，repo 池压根不跑，而选型最需要星数/活跃度。不含 code 池（选型不需要代码片段，省一轮池开销）。

**推荐用法**：

- 选型：`-Auto "tokio vs async-std" -AsJson` 或 `-Keyword "http client" -Language Rust -MinStars 1000 -AsJson`
- 资料：`-ResearchSources -Keyword "分布式锁的实现方式对比" -AsJson`（research 池吃自然语言）
- 代码证据：`-CodeEvidence -Keyword "connection_pool_timeout" -AsJson`（用标识符/函数名，不要用句子）

**已知边界**：多词 AND 会稀释召回（描述里没写全的词就出局）；同一意图换说法召回差异极大。中文主题词映射是**词表**不是翻译器：表外的中文主题词抽不出来（会告警），专业术语/新词请直接写英文。要"准确"，靠**多轮短词查询 + 交叉核对**，不要指望一次长句问对。

## MCP 服务端（`mcps.py --mcp`，v1.44.0）

```text
python mcps.py --mcp [--mcp-timeout 180]
```

stdio 传输：**逐行一个 JSON-RPC 2.0 消息**（不是 LSP 的 Content-Length 帧）；stdout 只有协议行，日志一律 stderr。

| 工具 | `-Serve` op | 接受参数（白名单，多一个就 `-32602`） |
|---|---|---|
| `search_repositories` | `repo` | `keyword`(必填) / `limit` / `maxResults` / `platforms` / `language` / `minStars` / `activeWithin` / `excludeArchived` / `license` |
| `search_auto` | `auto` | `keyword`(必填) / `limit` / `maxResults` / `language` / `minStars` / `site` |
| `search_code` | `code` | `keyword`(必填) / `limit` / `maxResults` / `language` / `repoScope` / `pathFilter` |
| `research` | `research` | `keyword`(必填) / `limit` / `maxResults` / `site` |
| `package_lookup` | `package` | `packages`(必填；生态:包名，逗号分隔) |
| `ping` | `ping` | — |

> 本表是这份白名单在文档里的**唯一登记处**：门 U-295-F 把这张表逐行读出来，与 `mcps.py` 的 `MCP_TOOL_OPS`
> 比"工具集合 / op / 每个工具的键集合"三项，**双向点名**。v1.77.0 之前它漏了 2 个工具与 6 个键，
> 而 SKILL.md 的同一张表是全的 —— 两份文档各说一套，没有任何门去对，用户照这份写 `license` 会被判成错参数。
>
> **两层都拒，不只是 MCP 层**（v1.79.0）：绕开 `mcps.py` 直接往 `-Serve` 的 stdin 写一行 JSON 时，未知键
> 一律回 `{"ok":false,"error":"unexpected request keys: <名字>","allowed":[...]}`，**不再静默按默认值检索**
> （拼错 `minStar` 曾会按默认 `minStars=100` 跑一轮、返回 0 条且无告警）。门 U-295-H 拿 PS 这张白名单与
> `MCP_TOOL_OPS` 逐 op 两向对账，并真起 `-Serve` 验证"拒 + 点名 + 合规请求照过"。
>
> **键名逐字匹配、大小写敏感**（v1.80.0）：`Keyword` / `MinStars` 这类变体在两层都会被判未知键。此前 PS 侧用
> 大小写不敏感的比较符，同一个 `MinStars` 在 `-Serve` 被放行（连值都用了）、在 `mcps.py` 被拒 —— 同一份输入
> 两层判定相反。唯一例外是协议键 `op`（PS 天然大小写不敏感地绑定它，且没有 python 对端可比）；门 U-295-H3
> 用 26 个 `(op, 变体)` 钉住"两层同判"，并给"全小写必须一条都不报"的阴性对照。

- `limit` = **每源页大小**（与 CLI `-Limit` 同义）；`maxResults` = 返回条数上限（0 = 不截断）。
- 结果经 `Merge-DedupResults` + `Set-UnifiedScore` 排名（与 CLI 同口径），每条含 `Score/Relevance/Popularity`。
- `--mcp-timeout`（默认 180s）超时 ⇒ **杀掉并重启** `-Serve`，回 `isError:true`（绝不让客户端空等）。
- 常驻进程会**逐请求重置**引擎状态/告警（否则第 N 次响应的 coverage 会带上前面请求的残留）。
- 支持的方法：`initialize` / `notifications/initialized` / `ping` / `tools/list` / `tools/call`；未知方法 `-32601`，坏 JSON `-32700`。
