## 引擎状态语义（v1.21.0，`coverage.Reasons`）

| 状态 | 含义 | 是否可信"0 命中" |
|---|---|---|
| `ok` | 检索成功且返回结果 | — |
| `empty` | 检索成功但 0 命中 | ✅ 可信（真的没有匹配） |
| `auth_missing` | 需要 token 但未设置/无效（如 GitHub code search 强制认证 401） | ❌ 未检索 |
| `tool_missing` | 缺本地工具（rg/ugrep/ast-grep） | ❌ 未检索 |
| `rate_limited` | 429/限流（可恢复降级） | ❌ 未检索 |
| `error` | 真异常 | ❌ 未检索 |

### EngineContract v1（v1.53.28 起，B2-1）

引擎函数**只返回一个对象**（不再返回裸数组）：

```
{ contract='engine/1', engine, kind, results=[], partial, elapsedMs,
  requests={attempted,succeeded,failed}, quota={class,limit,remaining,resetAt},
  failure=$null | @{reasonCode, reason} }
```

- **引擎不自报 status**：判定由池侧 `Resolve-EngineVerdict` 机械派生 —— 有产出无 failure ⇒ `ok`；
  零产出无 failure ⇒ `empty/zero-hit`；有产出有 failure ⇒ `degraded`（保留首因）；
  零产出有 failure ⇒ `blocked`（未执行类：缺凭据/被禁/健康跳过/配额耗尽/池没收工）或 `error`（执行了但失败）。
- 派生结果再由 `ConvertTo-LegacyEngineStatus` 映射回上表的内部状态串 ⇒ `coverage` 三分类**一字不动**。
- 旧引擎返回数组时由 `ConvertTo-EngineEnvelope` 现包 `engine/0`，**不派生 verdict**（`_engineStatus` + 池尾兜底原路生效）。
- `reasonCode` 直通 `coverage.ReasonCodes`：**迁移引擎不再走文案正则**（旧路径靠 `$rtxt -match '预算已用尽'` 之类反推 —— 改一句人读文案就改机器判定）。
- 已迁移（**四个核心引擎全部完成**）：**`HF`**（v1.53.28）、**`GitHub`**（v1.53.32）、**`DeepSeek`**（v1.53.33，
  唯一会走 402 的付费源）、**`GitLabBlobs`**（v1.53.34，唯一有自设调用预算 + 嵌套 runspace 池）。
  新增引擎请照它们的形状写，并在注册表 `Needs` 里加 `New-EngineEnvelope`（替换掉 `Set-EngineStatus`）。
- **`requests` 两种取法**（都已落地，选哪种看请求是否集中）：请求集中在一处的引擎**自己数**（`$req.attempted++` /
  `succeeded++` / `failed++`，三格恒等式 `attempted == succeeded + failed` 由夹具逐臂钉）；请求散在多处或跨越
  嵌套池的用 **`Get-ApiRequestLedgerByEngine`**（从 B2-6 的账本按 engine 聚合，天然含池内请求）。
  ★后者的前提是调用点已设 `$script:_ledgerEngine`（池包装块 / `Invoke-EngineSerial` / 嵌套池各一处；
  GitLabBlobs 另加了自己兜底赋值 —— 没设的后果是 `requests` 恒 0/0/0 的**假零**，比缺一项更难发现）。
- **`quota.class` 已知取值**（不在 schema 里，属封套内部事实）：`anonymous`（无需凭据，如 HF/GitHub 无令牌）、
  `prepaid`（预付费余额，如 DeepSeek）、`token`（凭据配额桶）、`none`（本次没发请求，如无 key 的 DeepSeek）。
  `limit`/`remaining` 一律**不猜**：要解析上游响应头或账户接口才有，猜错的余额会被拿去当决策依据。
- **`execution` 块**（v1.53.30，B2-5）：`{budgetMs, spentMs, reserveMs, truncated, skipped[], pools[]}`。口径：
  `budgetMs=0` = 未设预算（不编默认值）；`skipped[]` = 请求过但**没执行**的源（复用 `coverage.ReasonCodes`，含"总预算耗尽"那类文案）；
  `pools[]` 只列**真的经过并发池**的调度单元（单平台直连没有池，故为空）；`sufficient` 逐池、不放顶层。
- **`execution.ledger`**（v1.53.31，B2-6）：汇总 `{runId, rows, path, written, error}`；行级明细只写 JSONL
  （`MCPS_LEDGER=<path>`），载荷不自带几十行。口径：`rows` 必须等于 `metrics.Requests`（同点入账，门 U-261 真跑钉住）；
  `path=null` = **没开**（正常态），`error` 非空 = **开了但写失败** —— 两者严格区分，不合并成"0 行"；
  唯一键 `(runId, seq)`（seq 每轮重置）。行级 `reasonCode` 与 `coverage.ReasonCodes` **不是一回事**：
  前者是**单次尝试**的闭集（quota-exhausted / rate-limited / http-5xx / http-4xx / transport），后者是**引擎级**判定。
- **`Needs` 由门 U-259 校验**（v1.53.29）：对每个引擎从 `Func` 出发做 AST 传递闭包，
  闭包内每个本仓函数必须 ∈ 手写 `Needs` ∪ `Get-HttpLayerClosure`(43) —— **漏登记即红并指名**。
  这条专治 U-02/U-40 那类静默事故（runspace 里调用未定义命令会被 catch 吞成"没结果"）。
  反方向（手写但不可达）做棘轮：≤8 项、明细冻结，只许收紧。运行时仍用手写清单（全量派生留待 B3）。

> 一条**被纠正的前提**：源码曾断言「引擎在 runspace 内的 `Set-EngineStatus` 写不进父作用域」。2026-10-26 实测**不成立**
> （`_engineStatus` 是 ConcurrentDictionary 且经 `_injectVars` 按引用注入 ⇒ 父侧立即可见；并发写 6400 键零丢失）。
> 封套要治的是：状态是旁路（引擎早退就没人写）、reasonCode 靠文案正则、requests/quota 无逐引擎口径。

## coverage 输出契约（`-AsJson` 顶层 + `metrics.PerPlatformOutcome`）

- `Requested`：本次涉及引擎
- `Executed`：ok | empty
- `Blocked`：auth_missing | tool_missing
- `Degraded`：error | rate_limited
- `Reasons`：逐引擎原因（人读文本）
- `ReasonCodes`（U-120b）：逐引擎机器可读原因码，只列"未产出结果"的引擎：`missing-credential` | `tool-missing` | `network-unavailable` | `rate-limited` | `deadline` | `error` | `zero-hit` | `not-run` | `user-disabled`（被 `MCPS_DISABLE` 禁用的本模式引擎：**不进 `Requested`，只进本表**，两字段互不污染）
- `Verdict`：`full` | `partial` | `degraded` | `none` | `no-engines`（U-120：`none` = 请求了引擎但 `Executed=[]`，全 blocked/degraded；`partial`/`degraded` 只在 `Executed` 非空时出现；`no-engines` = 什么都没请求）
- `metrics.ExitCode`：**0 正常 / 2 工具缺失 / 3 认证缺失 / 4 降级**（"为什么不是全绿"的**归因码**）
- **`-Auto` 的判定字段**（v1.47.3）：`modes`（实际执行的模式数组）、`queryType` / `planSource` / `autoKeyword`
  （**仅 `-Auto` 有值，非 Auto 恒 null**）、`counts{repo,code,research}`（各模式结果条数，按模式块结算）。
  与 MCP `search_auto` 的响应**逐键同构**（U-209 双向守护）——此前这些只在控制台打印，`-AsJson` 的 Agent 看不见。
- **`doctor.deadlinePolicy`**（v1.47.5）：逐源生效截止。`Resolved[]` 每项 `{Engine, Seconds, Source, TableSeconds}`，
  `Source ∈ {table, default, cap, cap-or-scale, env, off}`；顶层还有 `HardCapSec` / `HardCapMultiModeSec` /
  `MultiModeScale` / `EnvOverride` / `CappedCount` / `Advice`。**数字与真实执行同源**（`Get-EngineDeadlineSec`），本表只标注来源。
  `CappedCount > 0` 时 `Advice` 非空，直接给出两个受支持旋钮（`MCPS_ENGINE_HARD_CAP_SEC=0` 全局放开、
  `MCPS_ENGINE_DEADLINE="HF=30"` 逐源覆盖且不被夹）——**只报数不给处置**等于让人去翻代码（v1.47.7）。
  实测（v1.47.9 起）：默认 `EngineHardCapSec=0`（关闭）⇒ **没有源被夹**，`CappedCount=0`、`Advice` 为空，
  表里 28/29/26 逐字生效。此前默认 10 时 21 个引擎里有 **17 个**被夹住（28/29/26 实际只等到 10s，表形同虚设）；
  设 `MCPS_ENGINE_HARD_CAP_SEC=10` 可复现旧行为，此时 `CappedCount>0` 且 `Advice` 非空。
  `PathDefaults` 给出三条路径的默认秒数（`Repo=29` / `Code=17` / `Research=17`）—— v1.47.6 起按注册表 `Kind` 取，
  此前一律用 research 的 17，repo 引擎的 `TableSeconds` 会标错。
- **`doctor.budgetPolicy`**（v1.47.6）：`PerPoolSec`（每池预算，默认 120）、`EnvOverride`、`PoolsInAuto`（3）、
  `WorstCaseSec`（= 每池 × 池数；`-Auto` 最坏 360）、`SharedAcrossPools`（当前 **false** = 每池独立计）。
  改共享预算是行为变更（后两个池会更早被砍），只报现状、不擅自改。
- **进程退出码**（v1.47.2 起）：`0` = 本轮**至少一个引擎执行过**（含真实 0 命中；`partial`/`degraded` 也算 0）；
  `2/3/4` = **一个都没查成**（`Verdict ∈ {none, no-engines}`），值与 `metrics.ExitCode` 同档。
  两者不等是**设计**：多源聚合下"有源被挡"几乎每轮成立，若进程码也跟着非 0 就变成常量噪声。

> Agent 判定规则：`Blocked`/`Degraded` 存在时**不能**把 0 命中当"确实没有"——先看 Reasons。

## `-ResearchBatch` 逐查询码与零命中（U-151/U-152）

批量结果 `queries[]` 的每项始终带 **`reasonCode`（小写单数）**，并保留原有的 `ReasonCodes`（逐引擎映射）与 `coverage.ReasonCodes`；与单条查询的枚举相同：`missing-credential / tool-missing / network-unavailable / rate-limited / deadline / error / not-run / user-disabled / zero-hit`。有命中的成功项为 `null`；**成功执行但无匹配**为 `zero-hit`，其 `coverage.Verdict=full`、`Status=ok`、`ResultCount=0` 不变；失败项如有多个引擎码，标量按上述顺序选第一个，避免哈希表遍历次序影响输出。外层 `coverage.ReasonCodes.Q1` 与失败项标量一致；成功零命中**不**计为失败。

`coverage.Verdict` 表示覆盖，不等于有没有结果：逐项 `none` = 请求了引擎但 `Executed=[]`；所有查询均无执行成功时批量顶层 `none`，全禁用则 `no-engines`；任何源已经成功执行却真实 `zero-hit`，仍按覆盖报 `full`／`partial`，由 `ResultCount` 与逐引擎码区分“没找到”和“没跑到”。批量包不是单条 `-AsJson` 根对象；可用 `schema/asjson.schema.json#/$defs/researchBatch` 校验。

## warnings[] 降级警示契约（v1.23.0）

引擎失败/降级写入顶层 `warnings[]`：`[Engine] 消息 (from: 来源 -> 去向)`。
示例：`[GrepApp] grep.app 匿名限流 429（10 req/min），本次跳过 (from: official API -> skip (rate_limited))`
**Agent 可审计"谁降级了、为什么、从哪到哪"，不再无声兜底**。

v1.37.9 起两类非引擎前缀（2026-09-28）：
- `[query] 低区分度词: …`（U-121/S1，词表 `Cfg.LowDiscriminationTerms`）与 `[query] MinStars=N 为高门槛档…`（U-113，`Cfg.MinStarsHighThreshold`）——查询侧只告警不改行为。
- `[coverage] 因缺凭据未请求: A, B; 已请求但失败: C`（U-115）——缺凭据源（`auth_missing`，请求未发出）与已请求但失败源（`Degraded`）分列；逐引擎码见 `coverage.ReasonCodes`。

输出清洗（U-124，D4 形态输入型负例，`Protect-ResultOutput` / `Build-RagContext` 同口径）：`Url` 查询串里凭据类参数值改 `<redacted>`；`Name/Desc/Preview/License` 剔除零宽与双向控制字符；描述里的"指令文本"原样保留为数据，不执行不删。门：`tests/test-u124-injection-negatives.test.mjs`（3 例 + canary）。

## MCPS_DISABLE 与时长预算（v1.33.0）

- `MCPS_DISABLE=grep.app,Sourcegraph`（逗号/分号/空白分隔，匹配引擎注册名或显示名，大小写不敏感）：
  被禁引擎**不进入调度与 `coverage.Requested`**，并写 `[Engine] 已按 MCPS_DISABLE 配置跳过 (from: engine registry -> skip (user-disabled))`——语义为"用户已知并排除"，与 `Degraded`（引擎失败）区分。
- `MCPS_TIME_BUDGET_SEC`（默认 120，0=不限）：并发编排 EndInvoke 循环超预算后 `Stop` 剩余引擎，
  保留已产出部分结果，被停引擎标 `error`（Reason="运行时长超预算"）→ 计入 `Degraded` + `ExitCode 4`。
- `-Doctor` 输出 `disabledEngines[]` 透出当前禁用配置。

## Stars 的 Unit 语义字段（v1.34.0）

跨源 Stars 热度代理语义不同，每条结果新增 `Unit` 字段显式声明（供 Agent 消费，避免跨源误读）：

## 仓库发现质量过滤（v1.46.7，U-202）

`-ActiveWithin <天>` / `-ExcludeArchived` / `-License "mit,apache-2.0"` 全部在**客户端**执行，不翻译成上游限定符：四源的限定符能力各不相同，翻译后同一组参数会得到不同候选集，用户无法判断"少掉的那几条"是上游没给还是被拦了。

|---|---|---|---|
| GitHub | ✅（结果字段 `Archived`） | ✅ `license.spdx_id` | `updated_at` |
| Codeberg | ✅（结果字段 `Archived`） | ❌ | `updated_at` |
| Gitee(so) | ❌ | ✅ `license[]` | `last_push_at` |
| GitLab(`/projects`) | ❌ | ❌ | `last_activity_at` |

缺字段时**不剔除**该条，并在 `warnings[]`（CLI）或 `filterNotes[]`（MCP）写 `GitLab 不返回 archived ⇒ 未过滤（N 条无法判断）`；`-License` 下"无 license 信息"的条目会被剔除并单列计数。过滤后条数可能少于 `-Limit`；若被剔除光，`coverage.Reasons` 记 `检索成功但质量过滤剔除全部 N 条`（**不是零命中**）。MCP `search_repositories` 另返回 `filtered{input,kept,archived,stale,licenseMismatch,licenseMissing,cutoff,notApplied}`。

## -ResearchBatch（U-114，R90）：同一进程并发研究查询

输入为 UTF-8 JSON **数组**（如 `["PowerShell runspace", "dot source", "agent tooling"]`）或 `{ "queries": ["…"] }`，1–64 项，每项须非空字符串；单项格式也支持。执行示例：`pwsh -NoProfile -File ./multi-platform-searcher.ps1 -ResearchBatch ./queries.json -AsJson -NoEnvFile -NoCache`。`-Keyword` / `-Auto` / `-Doctor` / `-CodeEvidence` 不得与批模式叠加；`-Limit`、`-Site`、`-NoProxyFix` 可传递给每条普通 `-ResearchSources` 查询。

外层 **RunspacePool** 同进程最多 4 条并发、默认整批 120 秒上限；每条委托到本脚本既有 `-ResearchSources -AsJson` 主流程，未为每条启动新的 `pwsh`。返回单个批包 `{version,mode:"research-batch",queries:[...],coverage,metrics}`：`queries[i]` 保留 `Index/Keyword/Status/ResultCount/results/coverage/ReasonCodes/metrics/warnings/Error`；失败或超时仍保留这一位置、`ResultCount=0`、`ReasonCodes.Batch=error|deadline`，**不将失败伪装成零命中**。`coverage.ReasonCodes.Q1…` 将逐条异常提升到批级；`no-engines`（全部被主动禁用）不是成功命中，`Status=no-engines` 且携带各引擎 `user-disabled`。读取结果前必须检查 `coverage.Executed/Blocked/Degraded`。原单条 `schema/asjson.schema.json` **不等同于**本批外层格式，逐条的内层 `coverage/results` 遵循已有契约。
**`metrics.FailedCount` 的口径是"非 `ok` 的查询数"**（`degraded` 也计入），不是"失败查询数"——
`degraded` 的条目仍可能带满量结果（实测两条 `degraded` ⇒ `FailedCount=2`，但 `ResultCount=76`）。
判"这条查询有没有结果"请看 `queries[i].ResultCount` 与 `Status`，不要只看 `FailedCount`。

性能验收用固定 9 查询（每条模拟等待 350 ms、1–4 个确定性结果，禁止网络），串行三轮取九查询总时长的 p95，与相同 runner / 查询 / limit 下的外层池对照；具体原始毫秒和逐条计数见 `reports/gates/r90-u114-20260929-evidence.md`。**这证明编排效率，不保证公网并发在外部限流、凭据缺失和不同时间点下结果数恒等；未实测所有研究端点的公网 9 查询 P@95。** 失败注入在系统临时目录，红绿件不写被测目录。

## -Auto 集成模式（v1.34.0）

`-Auto -Keyword "<查询>"`：内嵌 `query-planner.ps1` 分类 → `Convert-PlanToModes` 映射执行模式：

## -Package 精确包元数据（deps.dev，v1.46.3）

- **为什么是独立入口**：deps.dev **没有关键词检索端点**（`/v3alpha/search` 实测 404）。塞进 `-ResearchSources` 等于造一个"按定义必然 0 命中"的源，会污染 `coverage.Requested`；故改为 `-Package "<生态>:<包名>"`（生态：npm/pypi/cargo/go/maven/nuget）。
- **请求形状**（每包两次 GET，免 key、实测无 429）：
  1. `/v3alpha/systems/{system}/packages/{name}` → `versions[]`（`isDefault` / `isDeprecated` / `publishedAt`）
  2. `/v3alpha/systems/{system}/packages/{name}/versions/{version}` → `licenses` / `licenseDetails` / `advisoryKeys` / `links`
- **name 必须 `EscapeDataString`**：`npm:@types/node` 不编码实测 **404**，编码成 `%40types%2Fnode` 才 200；`go` 的模块路径同理（`github.com%2Fgin-gonic%2Fgin`）。
- **字段语义**（v1.47.7 补）：deps.dev 不提供 star/popularity，故结果恒为 `Stars=0`、`Popularity=0`、
  `Unit='none'`、`Score=0`。**`Unit='none'` 就是"该生态没有 star 概念"的标记**，不要读成"0 星包"；
  排序看 `Relevance`/`Score` 在本入口无意义（本入口不是检索，是按名精确取元数据）。
- **输出**：`Platform=deps.dev`、`Name=生态/包名`、`License`（`licenses` 空则回落 `licenseDetails[].license`）、`Updated`（ISO）、`Desc=default <ver> · <日期> · <N 个版本> · <M 条安全公告>`；`Stars=0` + `Unit=none`（该源没有热度概念）。
- **口径**：404 ⇒ `empty` + `ReasonCode=zero-hit`（**执行过、无此包**；记 `error` 会让 `Verdict=none`/退出码 4）；未知生态或格式错 ⇒ 参数期报错（非零退出）。
- **不做的**：依赖图（`/v3alpha/query` 是 POST 且要逐版本展开）、许可证合规判定（只透出 SPDX 串，不做策略判定）。
- 实测（2026-10-20）：单包两请求 0.3–2.7s；`go` 的 versions 可达 2365 条 / 689KB（`ConvertFrom-Json` 可承受，但别对同一包重复查）。

## 网络事实备忘（本机 2026-08-22）

- **grep.app 匿名 API**：本网络被 Vercel 反爬 challenge 长效 429（`X-Vercel-Mitigated: challenge`，与 UA/header 无关）——技能如实报 `rate_limited` + `Degraded` + `warnings[]`，**不是静默 0 命中**。换网络/出口 IP 可恢复。
- **Sourcegraph streaming**：**可用性随出口网络变化**。2026-10-20 复测：同一构建下 `curl`/引擎时而 `200`（流式返回，68.7s 才收齐 1 条）、时而 `403` + 17.6KB `Firewall Block` HTML。403 现按三档落状态：正文含 `Firewall Block` ⇒ `network_unavailable`（blocked，「出口被边缘防火墙拦，重试无效」）；匿名 403 ⇒ `network_unavailable`（未执行）；带 `SRC_TOKEN` 403 ⇒ `error`（令牌无权，不越权断言成网络问题）。别把它当"稳定兜底"——`MCPS_DISABLE=Sourcegraph` 可关。
- **GitHub code search**：未认证必然 401（10 req/min），认证 30 req/min。`sort`/`order` 官方标注 **"closing down"**（无日期）⇒ 本技能不传这两个参数，并由 U-189 静态门守着（含 `Accept: text/vnd.github.text-match+json`，否则 `Preview` 恒 null）。
- **searchcode（`-RepoScope`）**：只支持"指定仓库内"检索（缺 `repository` 直接 400），不是全局源；响应含 `context_before/context_after`（v1.46.1 起进 `Preview`）与 `truncated/has_more/total_matches`（进 `warnings[]` + `Desc.total`）。`context_lines` 保持 1（预览只取前后各一行、`PreviewLen=200`，服务端多给的行用不上）；`max_matches_per_file` 服务端默认 5、上限 50。
- **MCP 官方注册中心**：`/v0/servers` **默认只返回 30 条**且带 `metadata.nextCursor`；本技能显式 `limit=100`，且**只在 0 命中时**提示"仅扫描前 100 条"（有命中时提示是噪音）。客户端关键词过滤只覆盖这一页 —— 0 命中不等于全库没有。**服务端 `search=` 实测不可作默认路径**（2026-10-20）：命中时 1.9–6.1s、零命中全表扫描 **8–22s**（12s 两次超时），与 8s 引擎截止 / 当时的 10s 单源硬上限冲突；要用得先有 per-engine 硬上限（现无）。全库现有 **1200+ 条**、单页上限 100（`limit>100` ⇒ 422）。
- **Gitee API**：部分沙箱/网络被防火墙拦截（GitHub 白名单放行时 Gitee 可能不通），失败自动跳过不阻断。主通道是 `so.gitee.com` 搜索后端；回退的 v5 `/search/repositories` **匿名恒返空数组**（2026-10-20 实测：匿名 `[]`、带无效 token 反而 401）⇒ 无 `GITEE_TOKEN` 时 0 条记 `auth_missing`（未执行），有 token 仍 0 条记 `empty`。
- **OpenAlex 预算**：响应带 `X-RateLimit-Limit` / `-Remaining`（credits，默认 1000/天，按**网络 IP 共享**）；剩余 ≤10% 时进 `warnings[]`。429 时 `Retry-After` 会被折算成「约 N 分钟后重试（UTC 时刻）」；`mailto` 已不生效，免费 key（`MCPS_OPENALEX_API_KEY`）才自带独立预算。

## `-AsJson` 消费侧说明（U-130，2026-09-29）

`-AsJson` 时脚本会把**本进程** stdout 钉为 UTF-8（无 BOM），因此经管道（MCP 宿主 / Node `spawn` / `subprocess`）读取的 JSON 是 UTF-8 字节。消费方须**按 UTF-8 解码**（Node `setEncoding('utf8')`、Python `encoding='utf-8'`）；若消费方自己用 `powershell -Command "... | Out-String"` 之类再套一层 PowerShell 管道，外层进程也需自行钉 `[Console]::OutputEncoding = UTF8`，否则中日文会在**外层**折成 `?`（R69 三段定位：产出正确、捕获段失真）。文件落盘请用 `-AsJson > file` 在 pwsh 7 下（UTF-8）或显式 `[IO.File]::WriteAllText(..., UTF8)`。

**U-150 验收先保留 stdout 原始字节**：Python 用 `subprocess.run(..., stdout=PIPE).stdout.decode('utf-8', errors='strict')` 后再 `json.loads`；Node 先收 Buffer，再用 `TextDecoder('utf-8', {fatal:true})` 严格解码。若须保存原始产物，请直接落**捕获到的 bytes**（不是在宿主默认代码页里先转成字符串再 `WriteAllText`）；`…` 的 UTF-8 原始字节不应在落盘文件中变成 `鈥?`（更不能吞掉后续的 JSON 引号）。遇到坏文件先比对三段：产品原始 stdout 字节、捕获端解码出的字符串、最终文件字节；不要仅凭最后一段将宿主捕获错误归因到 `ConvertTo-Json`。
